## 📚 รายละเอียดปัญหาและวิธีแก้

### 1. 🟡 ตารางไม่มี Security Filter (ทุกคนโหลดทุกแถว)

**ตำแหน่ง:** ตารางทั้งตาราง  

**ทำไมต้องแก้:** ไม่มี Security Filter หมายความว่าทุกผู้ใช้จะโหลดข้อมูลทั้งตารางมาที่เครื่องตอน sync สำหรับตารางที่ใช้ร่วมกันทั้งทีมถือเป็นเรื่องปกติ แต่ถ้าแถวเยอะมากจะทำให้ sync ช้าและกินเน็ตมือถือ และยังไม่มีชั้นป้องกันถ้าวันหนึ่งมีการเพิ่มคอลัมน์อ่อนไหวในตารางนี้

**วิธีแก้ใน AppSheet Editor:**

1. ถ้าตารางนี้ทุกคนในทีมควรเห็นหมด — ปล่อยได้ แต่จดไว้ว่า "ห้ามเพิ่มข้อมูลส่วนบุคคลภายหลัง"
2. ถ้าอยากให้เห็นเฉพาะของตัวเอง ทำตามแบบที่แอปใช้อยู่: Data > ตารางนี้ > Security Filter ใส่ `=OR(USERROLE() = "ADMIN", [Email พนักงาน] = USEREMAIL())`
3. ถ้าตารางเป็นตารางอ่านอย่างเดียวทั้งทีม (เช่น ตารางราคา) การไม่มี filter ถือว่าเหมาะสม

### 2. 🟠 คอลัมน์ถูกทำเครื่องหมายว่าเป็นข้อมูลอ่อนไหว (Sensitive data)

**ตำแหน่ง:** คอลัมน์ `Scan_By`  

**ทำไมต้องแก้:** AppSheet ระบุว่าคอลัมน์นี้มีข้อมูลส่วนบุคคล/อ่อนไหว ผู้ใช้ทุกคนที่เห็นตารางนี้จะเห็นคอลัมน์นี้ด้วย ควรคุมการแสดงผลให้เฉพาะบทบาทที่จำเป็นต้องใช้เท่านั้น

**สูตร/ค่าปัจจุบัน:**
```
USEREMAIL()
```

**วิธีแก้ใน AppSheet Editor:**

1. เปิด Data > ตารางนี้ > คอลัมน์ดังกล่าว > เปิด **Hide?** แล้วคุมด้วย Show_If เช่น `=USERROLE() = "ADMIN"`
2. หรือใช้ Slice ที่ตัดคอลัมน์นี้ออกสำหรับผู้ใช้ทั่วไป

### 3. 🟠 สูตรใช้ SELECT() ซึ่งสแกนทั้งตารางที่อ้างถึง

**ตำแหน่ง:** คอลัมน์ `จำนวน_ทั้งหมด`  

**ทำไมต้องแก้:** SELECT() ต้องไล่อ่านทุกแถวของตารางปลายทางทุกครั้งที่คำนวณ ยิ่งเป็น Virtual Column จะยิ่งคำนวณซ้ำบ่อย เมื่อข้อมูลโตขึ้นเป็นพัน ๆ แถว แอปจะเริ่มช้าชัดเจน โดยเฉพาะหน้าจอที่เปิดทีเดียวแสดงหลายแถว (deck/table)

**สูตร/ค่าปัจจุบัน:**
```
COUNT( UNIQUE( SELECT( ตารางงานประจำวัน[Invoice No], [Plan Delivery] = [_THISROW].[เลือกวันที่] ) ) )
```

**วิธีแก้ใน AppSheet Editor:**

1. ถ้าผลลัพธ์คือค่าเดียว ใช้ **LOOKUP()** แทน (เร็วกว่าเพราะหยุดเมื่อเจอ)
2. ถ้าอ้างแถวผ่านคอลัมน์ Ref อยู่แล้ว ใช้การเขียนแบบจุด `[RefColumn].[FieldName]` แทน SELECT ทั้งชุด
3. ทำให้เงื่อนไข SELECT แคบลง เช่น กรองด้วยวันที่/สถานะก่อน แล้วค่อยคำนวณ
4. ถ้าค่านี้ไม่จำเป็นต้องเรียลไทม์ พิจารณาเปลี่ยนเป็นคอลัมน์จริงที่ Action/Bot คำนวณเก็บให้ (ลดภาระตอน sync)

### 4. 🟠 สูตรใช้ SELECT() ซึ่งสแกนทั้งตารางที่อ้างถึง

**ตำแหน่ง:** คอลัมน์ `จำนวน_สแกนแล้ว`  

**ทำไมต้องแก้:** SELECT() ต้องไล่อ่านทุกแถวของตารางปลายทางทุกครั้งที่คำนวณ ยิ่งเป็น Virtual Column จะยิ่งคำนวณซ้ำบ่อย เมื่อข้อมูลโตขึ้นเป็นพัน ๆ แถว แอปจะเริ่มช้าชัดเจน โดยเฉพาะหน้าจอที่เปิดทีเดียวแสดงหลายแถว (deck/table)

**สูตร/ค่าปัจจุบัน:**
```
COUNT( UNIQUE( SELECT( ตารางงานประจำวัน[Invoice No], AND( [Plan Delivery] = [_THISROW].[เลือกวันที่], [ScanStatus] = "สแกนรับแล้ว" ) ) ) )
```

**วิธีแก้ใน AppSheet Editor:**

1. ถ้าผลลัพธ์คือค่าเดียว ใช้ **LOOKUP()** แทน (เร็วกว่าเพราะหยุดเมื่อเจอ)
2. ถ้าอ้างแถวผ่านคอลัมน์ Ref อยู่แล้ว ใช้การเขียนแบบจุด `[RefColumn].[FieldName]` แทน SELECT ทั้งชุด
3. ทำให้เงื่อนไข SELECT แคบลง เช่น กรองด้วยวันที่/สถานะก่อน แล้วค่อยคำนวณ
4. ถ้าค่านี้ไม่จำเป็นต้องเรียลไทม์ พิจารณาเปลี่ยนเป็นคอลัมน์จริงที่ Action/Bot คำนวณเก็บให้ (ลดภาระตอน sync)

### 5. 🟠 เก็บจำนวนเงินเป็นชนิด Text

**ตำแหน่ง:** คอลัมน์ `สรุปยอด`  

**ทำไมต้องแก้:** ข้อความ (Text) รวมยอด เรียงลำดับ หรือเทียบมาก-น้อยไม่ได้แบบตัวเลข สูตรอย่าง SUM()/TOTAL() จะพังหรือให้ผลผิด และถ้ามีตัวอักษรปนเข้าไป (เช่น "200 บาท") จะยิ่งแก้ยากภายหลัง แนะนำแก้ตั้งแต่ยังมีข้อมูลไม่มาก

**สูตร/ค่าปัจจุบัน:**
```
"📋 " & [จำนวน_ทั้งหมด] & " ✅ " & [จำนวน_สแกนแล้ว] & " ⏳ " & [จำนวน_รอสแกน]
```

**วิธีแก้ใน AppSheet Editor:**

1. เปิด Data > ตารางนี้ > คอลัมน์ดังกล่าว เปลี่ยน Type เป็น **Price** (หรือ Decimal ถ้าไม่ต้องการ ฿)
2. เปิด Google Sheets ล้างค่าที่มีตัวอักษรปน ให้เหลือแต่ตัวเลข (เช่น ลบคำว่า "บาท" ออก)
3. ถ้าคอลัมน์นี้ต้องเก็บข้อความปนจริง ๆ ให้สร้างคอลัมน์ตัวเลขแยกต่างหากไว้คำนวณ ส่วน Text ไว้แสดง
