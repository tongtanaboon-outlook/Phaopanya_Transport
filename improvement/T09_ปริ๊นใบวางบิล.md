## 📚 รายละเอียดปัญหาและวิธีแก้

### 1. 🟡 ตารางไม่มี Security Filter (ทุกคนโหลดทุกแถว)

**ตำแหน่ง:** ตารางทั้งตาราง  

**ทำไมต้องแก้:** ไม่มี Security Filter หมายความว่าทุกผู้ใช้จะโหลดข้อมูลทั้งตารางมาที่เครื่องตอน sync สำหรับตารางที่ใช้ร่วมกันทั้งทีมถือเป็นเรื่องปกติ แต่ถ้าแถวเยอะมากจะทำให้ sync ช้าและกินเน็ตมือถือ และยังไม่มีชั้นป้องกันถ้าวันหนึ่งมีการเพิ่มคอลัมน์อ่อนไหวในตารางนี้

**วิธีแก้ใน AppSheet Editor:**

1. ถ้าตารางนี้ทุกคนในทีมควรเห็นหมด — ปล่อยได้ แต่จดไว้ว่า "ห้ามเพิ่มข้อมูลส่วนบุคคลภายหลัง"
2. ถ้าอยากให้เห็นเฉพาะของตัวเอง ทำตามแบบที่แอปใช้อยู่: Data > ตารางนี้ > Security Filter ใส่ `=OR(USERROLE() = "ADMIN", [Email พนักงาน] = USEREMAIL())`
3. ถ้าตารางเป็นตารางอ่านอย่างเดียวทั้งทีม (เช่น ตารางราคา) การไม่มี filter ถือว่าเหมาะสม

### 2. 🟠 สูตรใช้ FILTER() ซึ่งสแกนทั้งตารางที่อ้างถึง

**ตำแหน่ง:** คอลัมน์ `ผลลัพท์`  

**ทำไมต้องแก้:** FILTER() ทำงานเหมือน SELECT() คือไล่ทุกแถว ใช้กับ Virtual Column จะเป็นตัวถ่วงประสิทธิภาพหลักของแอปเมื่อข้อมูลโต

**สูตร/ค่าปัจจุบัน:**
```
FILTER("ข้อมูลการวางบิล",(AND([ชื่องาน]=[_THISROW].[ชื่องาน], [วันที่]>=[_THISROW].[StartDate],[วันที่]<=[_THISROW]. [EndDate])))
```

**วิธีแก้ใน AppSheet Editor:**

1. ถ้าจุดประสงค์คือ "รายการที่อ้างถึงแถวนี้" ให้ใช้ **REF_ROWS()** ที่ใช้คอลัมน์ Ref โดยตรง (เร็วกว่าชัดเจน)
2. จำกัดขอบเขตเงื่อนไขให้แคบที่สุด และหลีกเลี่ยงการเรียก FILTER ซ้อนในลูป
3. ค่าที่ไม่ต้องเรียลไทม์ ให้ Bot คำนวณแล้วเขียนเก็บเป็นคอลัมน์จริง

## 🟡 ข้อแนะนำเพิ่มเติม (ทำได้ภายหลัง ไม่เร่งด่วน)

**คอลัมน์ไม่มีคำอธิบาย (Description)** — พบ 4 จุด

วิธีการเดียวกันทุกจุด: 
คอลัมน์ที่ยังไม่มีคำอธิบาย (เติมช่อง Description ของแต่ละคอลัมน์):
`ID_ปริ๊นใบวางบิล`, `ราคารวม`, `วันที่ออกเอกสาร`, `ผลลัพท์`

**สูตรใช้ SELECT() ซึ่งสแกนทั้งตารางที่อ้างถึง** — พบ 1 จุด

วิธีการเดียวกันทุกจุด: ถ้าผลลัพธ์คือค่าเดียว ใช้ **LOOKUP()** แทน (เร็วกว่าเพราะหยุดเมื่อเจอ)
คอลัมน์ที่เกี่ยวข้อง: `ราคารวม`
